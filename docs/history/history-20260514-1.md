**Claude**: 了解了项目现状。目前的问题是：项目宗旨是"收集和开发 AI 辅助编码工具"，但目录结构只体现了两个零散的工具，缺乏可扩展的组织模式。

以下是我的方案分析：

## 现状问题

1. **组织不一致** — `ccstatus/` 是独立目录，`skills/` 是分类目录，`hooks/` 散落在 `.claude/` 下，没有统一模式
2. **缺少索引** — 没有 README，无法快速了解有哪些工具可用
3. **工具元信息缺失** — `ccstatus/` 没有 README 说明用途、用法、依赖
4. **有垃圾文件** — 多个 `:Zone.Identifier` 文件（Windows 下载残留）
5. **Skill 重复** — `skills/` 和 `.claude/skills/` 存在手动复制

## 建议的目录结构

```
ai-coding-tools/
├── CLAUDE.md
├── README.md                      # 项目总览 + 工具索引
├── .gitignore
├── skills/                        # Skill 集合（已存在，保留）
│   └── init-claude-md/
│       ├── README.md              # 补充：用途、调用方式
│       ├── SKILL.md
│       ├── scripts/
│       ├── references/
│       └── evals/
├── tools/                         # 工具集合（新增，替代 ccstatus/）
│   └── ccstatusline/              # 从 ccstatus/ 迁移
│       ├── README.md              # 用途、安装、配置说明
│       └── setup.sh               # 从 setup-ccstatusline.sh 重命名
├── hooks/                         # Hook 脚本集合（新增）
│   └── record-history.js          # 从 .claude/hooks/ 提取源文件
├── configs/                       # 配置模板/预设（预留）
│   └── ...
├── docs/                          # 文档（已存在，保留）
│   ├── ai-coding-tools/
│   │   └── info.md
│   └── history/
└── .claude/                       # Claude Code 运行时配置
    ├── settings.local.json
    ├── hooks/                     # 运行时副本（安装时复制）
    └── skills/                    # 运行时副本（安装时复制）
```

## 关键设计决策

| 决策点 | 方案 | 理由 |
|--------|------|------|
| 按类型还是按平台组织 | **按类型**（skills/ tools/ hooks/） | 不同类型结构、部署方式不同，按类型更清晰 |
| `ccstatus/` 是否改名 | 迁移到 `tools/ccstatusline/` | 与 npm 包名一致，且 tools/ 下可放更多工具 |
| hooks 源文件放哪 | 顶层 `hooks/`，`.claude/hooks/` 是安装副本 | 源码和运行时分离，.claude/ 不应手动编辑 |
| README.md | 新增顶层 README + 每个工具 README | 顶层做索引，工具内做详细说明 |
| configs/ | 预留但不创建 | 现在没有内容，YAGNI，但有位置规划 |

## 需要确认的问题

1. **ccstatus → tools/ccstatusline 的迁移**：你同意这个改名和搬迁吗？
2. **hooks/ 分离**：record-history.js 源文件提到顶层 hooks/，`.claude/hooks/` 作为安装目标，这样合理吗？还是你觉得都放 `.claude/hooks/` 更简单？
3. **configs/ 预留目录**：是否现在就创建（空目录），还是等有内容再说？
4. **Zone.Identifier 清理**：是否删除那些 `:Zone.Identifier` 文件？
5. **是否需要统一的安装脚本**：比如一个顶层 `install.sh`，交互式选择要安装哪些工具？

请看看这个方案，有想法随时调整。
